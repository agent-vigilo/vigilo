# Coordinator Once Command

How `vigilo coordinator once` executes one configurable bounded orchestration
cycle and exits. It first resumes expired `creating` runs, then performs chunk
lease recovery, dispatch, receipt aggregation, finalization, and outbox publication. Dispatch work is
claimed through a `run_id + run_shard` cursor, and each operation selects a
partition-local chunk window before inserting one outbox event record per chunk.

## Decision Flow

<Mermaid value={decisionFlowDiagram} />

Receipt aggregation visits ready shards in fair rounds, revisiting shards with
remaining ready work within separate per-database page and scheduling-time budgets. Independent
shards and databases advance with bounded concurrency. Each page has its own
transaction and ownership claim; expiry of the scheduling budget stops additional
page admission while in-flight work remains subject to the database deadline.
See the [aggregation controls](/docs/architecture/structure/components/coordinator/#receipt-aggregation-controls).

Finalization has its own candidate limit and reads summaries in one batch per
execution database without advancing receipt aggregation. Unavailable, open, or
invalid shard summaries defer only their candidate; other runs continue. See the
[settlement contract](/docs/architecture/state/run-lifecycle/#settlement-and-partial-results).
