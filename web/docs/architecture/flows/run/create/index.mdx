# Run Create Command

`vigilo run create` validates profile and dataset inputs and records a durable
`creating` run before work can become visible to workers.

With inline or file dataset inputs, creation stores canonical case membership,
assigns execution placements, and seeds those placements idempotently. If
immediate seeding cannot finish, the same run ID remains available for coordinator
recovery. Dispatch cursors appear only in the transaction that changes a fully
seeded run to `pending`.

With `--dataset-upload-id`, `--storage-config`, and `--prepare-only`, creation
consumes a finalized catalog reference and publishes a verified immutable run
plan in bounded passes. It stores compact file references and shard totals,
without copying case payloads into control storage. The run remains `creating`
with a ready plan and no dispatch cursors. Explicit retries retain the same run
ID; the SQL seed-recovery coordinator does not claim this preparation path.
See [Run Preparation](/docs/architecture/case-storage/run-preparation).

Creation also resolves every evaluator reference to an exact registry id,
artifact hash, supported ABI, host adapter, and runtime version. This evaluator
execution plan and the complete scoring-policy hash are copied into each run
snapshot. Workers verify both hashes before executing any case.
