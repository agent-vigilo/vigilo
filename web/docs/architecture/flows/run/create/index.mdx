# Run Create Command

`vigilo run create` validates profile and dataset inputs and records a durable
`creating` run before work can become visible to workers.

Inline and file YAML/JSON inputs are admitted through bounded dataset ingestion;
`--dataset-upload-id` reuses a finalized catalog entry. Both paths publish the
same verified immutable configuration and run plan. Case payloads and ordered
membership remain in blob storage.

Execution admission seeds compact references and scheduling rows in bounded
pages. It verifies exact local chunk membership before one control transaction
publishes routes and dispatch cursors and changes the run to `pending`. A
coordinator resumes requested admission after interruption. `--prepare-only`
holds a ready plan without requesting execution. Retry with the same `--run-id`
and inputs, omitting that flag, to admit it.

Every evaluator reference is frozen to an exact registry ID, artifact hash, ABI,
host adapter, and runtime version. Workers verify the immutable configuration and
assigned case membership before execution. See
[Run Preparation](/docs/architecture/case-storage/run-preparation) for storage
configuration, limits, ownership, cancellation, and recovery.
