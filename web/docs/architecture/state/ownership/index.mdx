# State Ownership

Which process <GlossaryTerm term="owner">owns</GlossaryTerm> each state
transition and which database guard prevents conflicting writers.

<Mermaid value={ownershipDiagram} />

Database <GlossaryTerm term="claim">claims</GlossaryTerm> and
<GlossaryTerm term="lease">leases</GlossaryTerm> divide work. A
<GlossaryTerm term="claim-token">claim token</GlossaryTerm> fences settlement;
a <GlossaryTerm term="row-lock">row lock</GlossaryTerm> serializes conflicting
transactions; and the cooperative
<GlossaryTerm term="admission-lock">admission lock</GlossaryTerm> excludes shard
movement from normal writers. Control-plane changes use
<GlossaryTerm term="route-cas">route CAS</GlossaryTerm>, while data-plane writes
validate the <GlossaryTerm term="write-epoch">write epoch</GlossaryTerm>.
Prepared shard-move targets additionally validate the move ID, monotonic claim
generation, and opaque claim token in the target mutation transaction.

## Notes

- The create command owns input validation and the first durable `creating`
  transaction; other CLI commands cancel and read eligible state.
- Coordinators own expired run-creation recovery, expired chunk lease recovery,
  run dispatch, receipt aggregation, summary sealing, run finalization, and outbox publishing.
- Workers own chunk leases, attempt leases, execution attempt allocation, retry scheduling, and execution/attempt terminal transitions. Chunk-local worker state is addressed by `run_id + run_shard + chunk_id`.
- Chunk-ready messages carry the execution alias and write epoch. Workers use
  the hinted pool without a control lookup on the normal path; a rejected hint
  triggers cache invalidation and an authoritative route refresh.
- Database guards are the authority boundary: creation and coordinator leases,
  idempotent seed checks, shared run-state locks, chunk and attempt leases,
  conflict keys, current-attempt checks, worker ownership checks, and outbox
  delivery claim tokens prevent stale writes.
- Shard-move takeover installs a higher generation under exclusive target
  admission. In-flight target writes finish before takeover; later writes from
  an older generation are rejected before mutation.

Terminal producers share the chunk-before-attempt lock order with result writers.
A chunk receipt and its terminal state commit together. Aggregators use a separate
nonblocking transaction-scoped claim and shared movement admission for each page;
workers never take the aggregation claim. Sealed summaries and chunk receipts are
immutable. Movement copies receipts, consumption identities, and checkpoints so
aggregation resumes at the new owner. See the [settlement contract](/docs/architecture/state/run-lifecycle/#settlement-and-partial-results).
