# Vigilo.toml

The <GlossaryTerm term="evaluator-manifest">`Vigilo.toml` evaluator manifest</GlossaryTerm>
tells `vigilo` how to prepare and publish an evaluator WebAssembly component.
Source manifests live beside the evaluator crate
<GlossaryTerm term="package-manifest">`Cargo.toml` package manifest</GlossaryTerm>.
Portable manifests live beside `evaluator.wasm` and contain all publication metadata.

---

## Portable Package Manifest

`vigilo evaluator package` generates this form. It has no Cargo or source-file
references and does not contain build profiles. The placeholders below represent
64-character lowercase hexadecimal BLAKE3 hashes generated by the command:

```toml
format = "vigilo/evaluator-package/v1"

[package]
name = "sentiment-basic-en"
version = "0.1.0"
description = "Basic English sentiment evaluator"
tags = ["sentiment"]

[package.metadata]
language = "en"

[artifact]
path = "evaluator.wasm"
blake3 = "<hash of the exact packaged Wasm bytes>"

[wit]
package = "vigilo:evaluator"
world = "evaluator-world"
interface = "evaluator"
version = "1.0.0"
contract_hash = "<hash of the supported WIT contract>"
```

- `format` selects the strict portable-package schema; unknown fields are rejected.
- Package `name` contains ASCII letters, digits, underscores, or hyphens;
  `version` is a semantic version. Both must match the Wasm's embedded identity.
- Description, string tags, and the metadata table become registry metadata.
- `artifact.path` is exactly `evaluator.wasm`; its hash covers the bytes as stored,
  including the embedded package identity. Publication does not rewrite them.
- The WIT fields must resolve to a supported host ABI and its exact contract hash.
  Vigilo selects its own adapter and verifies typed component linking.

The manifest is limited to 1 MiB and Wasm to 64 MiB. Compressed and expanded
archives are limited to 66 MiB. Archives contain exactly the two root regular
files `Vigilo.toml` and `evaluator.wasm`; duplicate members, directories, links,
extra files, and nonzero trailing data are rejected. Directory inputs also require
regular manifest and Wasm files. No archive contents are extracted to disk.

## Source Manifest

The following sections describe the source-package form used while developing
an evaluator. Use [Publishing Evaluators](../guides/publishing.mdx) to generate a
portable package from it.

## File Location

Place `Vigilo.toml` in the evaluator crate directory:

```text
my-evaluator/
  Cargo.toml
  Vigilo.toml
  src/
    lib.rs
```

## Complete Example

```toml
[package]
manifest = "Cargo.toml"
description = "Example evaluator"
tags = ["example", "quality"]

[package.metadata]
owner = "evaluators-team"
tier = "example"

[wit]
path = "../../vigilo/wit/evaluator/v1.0.0/evaluator.wit"
world = "evaluator-world"
package = "vigilo:evaluator"
version = "1.0.0"
interface = "evaluator"
strict = true

[profile.dev]
wasm = "wasm32-wasip2/debug/my_evaluator.wasm"

[profile.release]
wasm = "wasm32-wasip2/release/my_evaluator.wasm"
```

---

## `[package]`

### `manifest`

Required. Path to the Cargo manifest file, relative to `Vigilo.toml`.

```toml
[package]
manifest = "Cargo.toml"
```

Source-package publishing supports `Cargo.toml`. `vigilo` reads evaluator `name`, `version`, Cargo description, Cargo keywords, and optional `[package.metadata.vigilo]` from this manifest.

### `description`

Optional. Human-readable evaluator description stored in the registry. When present, this overrides the Cargo package description.

```toml
[package]
description = "Basic English-only lexicon sentiment evaluator"
```

### `tags`

Optional. Searchable evaluator tags stored in the registry. When present, these override Cargo package keywords.

```toml
[package]
tags = ["sentiment", "classification", "example"]
```

### `[package.metadata]`

Optional. Extra evaluator metadata stored as JSON in the registry. When present, this overrides `[package.metadata.vigilo]` from `Cargo.toml`.

```toml
[package.metadata]
owner = "evaluators-team"
tier = "example"
```

## `[wit]`

Required for publication. Declares the immutable
<GlossaryTerm term="wit-contract">WIT contract</GlossaryTerm> implemented by the
evaluator.

```toml
[wit]
path = "../../vigilo/wit/evaluator/v1.0.0/evaluator.wit"
world = "evaluator-world"
package = "vigilo:evaluator"
version = "1.0.0"
interface = "evaluator"
strict = true
```

Fields:

- `path`: path to the WIT file, relative to `Vigilo.toml`
- `world`: expected WIT world name
- `package`: expected WIT package name
- `version`: expected WIT package version
- `interface`: expected exported evaluator interface
- `strict`: supported ABI declarations are always verified, even when this is
  `false`; the flag does not disable contract checks

Publication fails when `[wit]` is omitted, the declared ABI is unsupported, the
referenced WIT does not match the declaration, or the compiled component does
not link against the selected host adapter. Use `strict = true` for clarity.

`v1.0.0` is the supported contract. See
[Evaluator Compatibility](../guides/evaluator-compatibility.mdx) for exact
identity checks, artifact pinning, and adapter isolation.

## `[profile.<name>]`

Required for every <GlossaryTerm term="build-profile">build profile</GlossaryTerm>
you want to publish. Each profile maps a name to a compiled Wasm artifact path.

```toml
[profile.release]
wasm = "wasm32-wasip2/release/my_evaluator.wasm"
```

The `wasm` path is joined to Cargo's target directory for the evaluator package. With the default Cargo target directory, the path above resolves to:

```text
target/wasm32-wasip2/release/my_evaluator.wasm
```

Common profiles:

| Profile | Publish selection |
|---------|-------------------|
| `dev` | default when no profile flag is provided |
| `release` | selected by `vigilo evaluator publish <path> --release` |
| custom | selected by `vigilo evaluator publish <path> --profile <name>` |

## Registry Identity

Published evaluators use the strict identifier format:

```text
<namespace>/<name>:<version>
```

CLI publishing inserts into the built-in `vigilo` namespace. Source packages read
`name` and `version` from `Cargo.toml`; portable packages declare them in
`Vigilo.toml` and must match the embedded Wasm identity.

The selected profile chooses which artifact path to publish; it is not part of
the <GlossaryTerm term="evaluator-identifier">evaluator identifier</GlossaryTerm>.
Publishing changed content under an existing identifier is
rejected. Bump the `Cargo.toml` version before publishing changed evaluator
behavior or contract shape.

---

## Stale Build Detection

`vigilo` compares the modification time of the selected wasm artifact against `Cargo.toml`. If the manifest was modified more recently than the wasm, publish fails with a stale-build error.

Rebuild the selected profile before publishing:

```bash
cargo build --manifest-path evaluators/my-evaluator/Cargo.toml --target wasm32-wasip2 --release
vigilo evaluator publish ./evaluators/my-evaluator --release
```
